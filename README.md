# OddBid

엉뚱한 물건에 입찰하고 비밀 미션을 달성하는 실시간 멀티플레이 경매 심리전 게임.

Vue 3 + TypeScript + Vite로 화면을, Node.js + Colyseus로 게임 서버를 구성했습니다. 회원가입 없이 닉네임과 방 코드로 참여합니다.

## 실행

Node.js 22.12 이상이 필요합니다. 개발·검증에는 Node.js 24를 사용했습니다.

```sh
npm ci
npm run dev
```

[http://localhost:5173](http://localhost:5173)을 열면 됩니다. 웹은 5173, 게임 서버는 2567 포트를 사용합니다. 화면의 **혼자 연습**으로 봇 2명과 플레이하거나, 방을 만든 뒤 친구에게 링크/코드를 공유하세요. 모두 준비한 다음 방장이 경매를 시작합니다.

같은 Wi-Fi의 다른 기기에서는 개발 PC의 LAN IP로 접속합니다(예: `http://192.168.0.10:5173`). `localhost` 링크는 다른 기기에서 사용할 수 없습니다. 네트워크 접근과 방화벽 허용은 별도로 필요합니다.

빌드한 버전은 게임 서버가 웹 정적 파일까지 같은 주소에서 제공합니다.

```sh
npm run build
npm start
```

[http://localhost:2567](http://localhost:2567)에서 실행됩니다. 포트 변경은 `PORT=3000 npm start`로 할 수 있습니다. 웹과 게임 서버를 별도로 호스팅할 때는 웹 빌드 전에 `VITE_SERVER_URL`에 게임 서버의 WebSocket 주소를 지정합니다. 인터넷 공개 환경에서는 HTTPS/WSS를 사용하세요.

## 게임 규칙

- 인원: 3~6명. 혼자 체험하기는 사람 1명과 봇 2명입니다.
- 시작 자금: 각자 100코인. 실제 돈과 관계없는 게임 점수입니다.
- 한 게임: 고무오리, 주전자, 카세트테이프, 모형 로켓 등 30종 중 서로 다른 5종을 무작위로 골라 총 5라운드를 진행합니다. 한 게임에서 같은 물건이 다시 나오지 않습니다.
- 입찰: 현재 최고가보다 최소 5코인 높게, 5코인 단위로 입찰합니다. 잔액을 초과하거나 자기 최고가를 다시 올릴 수 없습니다.
- 시간: 라운드당 25초. 마감 후 4초 동안 낙찰 결과를 보여줍니다. 서버에 마감 전에 도착한 입찰만 인정됩니다.
- 정산: 마감 시 최고 입찰자의 코인만 차감하고 물건을 지급합니다. 입찰이 없으면 유찰됩니다.
- 비밀 미션: 게임 시작 시 서로 다른 미션을 받습니다. 각자의 미션은 본인에게만 전달되며 마지막 결과에서 공개됩니다.
- 수집 미션: 물건별 수집 미션 30개와 일반 미션 2개 중 배정합니다. 미션과 출품 물건은 별도로 추첨하므로 **목표 물건이 이번 게임에 나오지 않을 수도 있습니다.** 대기실·게임 방법·개인 수집 미션에 이 내용을 안내하며, 실제 목표 물건을 낙찰받았을 때만 수집 미션 보너스가 적용됩니다.
- 최종 점수: **남은 코인 + 수집한 물건의 가치 + 달성한 미션 보너스**. 총점이 같으면 공동 순위입니다.
- 다시 하기: 결과 화면에서 방장이 대기실로 돌아가면 코인과 미션이 초기화됩니다.

## 포함된 기능

방 만들기·코드 참가·초대 링크, 준비 및 방장 권한, 5라운드 실시간 경매, 입찰 기록과 반응 이모지, 개인 미션 확인, 라운드별 낙찰, 최종 점수와 미션 공개, 재경기, 봇 연습방, 모바일 레이아웃, 새로고침/일시 끊김 후 재접속을 지원합니다.

화면은 차콜·살구빛 주홍·회백색, 고운돋움 제목과 Nunito 숫자, 둥근 패널과 물건별 SVG 그림을 사용합니다.

## 구조

```text
apps/web/         Vue 화면, 컴포넌트, 연결 composable
apps/server/      Colyseus 방, 독립 게임 엔진, HTTP 서버
packages/shared/  공개 메시지 타입, 아이템, 미션 정의
tests/            실제 클라이언트 통합 테스트와 브라우저 테스트
```

공통 패키지는 가능한 미션의 정의만 공유합니다. 누구에게 어떤 미션이 배정되었는지는 서버의 비공개 맵에만 저장합니다. 공개 스냅샷과 본인 전용 메시지를 분리하며, 입찰 금액·순서·잔액·마감·낙찰·점수는 서버에서 검증합니다.

입찰 메시지는 `{ auctionId, amount }`입니다. 서버가 매 경매에 새 UUID를 발급하고 공개 스냅샷에 포함하며, 클라이언트는 입찰 버튼을 누를 때 표시 중인 ID를 함께 보냅니다. 누락·잘못된 ID와 이전 라운드·이전 게임의 ID는 게임 상태를 바꾸지 않고 거절합니다. 오래된 입찰은 현재 물건과 입찰가를 다시 확인하도록 안내하며 자동 재전송하지 않습니다. **기존 `{ amount }` 요청과 호환되지 않으므로 프런트엔드와 서버를 함께 갱신해야 합니다.**

현재 고정한 Colyseus SDK 0.18.4의 소켓 생성 코드가 WebKit에서 잘못된 프로토콜 오류를 내는 문제를 브라우저 빌드 단계에서 보정합니다(`apps/web/build/colyseus-browser.ts`). Node 서버/SDK 파일은 수정하지 않습니다. SDK를 업그레이드할 때 해당 보정의 필요성을 검토하고 브라우저 테스트를 실행해야 합니다.

## 검증 명령

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run test:dev
npm run format:check
```

브라우저가 설치되어 있지 않다면 먼저 `npx playwright install chromium webkit`을 실행하세요. `npm test`는 순수 규칙 테스트와 실제 WebSocket 클라이언트 통합 테스트를 실행합니다. 브라우저 테스트는 짧은 라운드 시간을 사용하는 별도 테스트 서버를 실행합니다. 이 설정은 참가자 메시지로 변경할 수 없습니다.

`npm run test:dev`는 개발 서버가 꺼진 상태에서 실행하세요. 5173/2567 포트에 서버를 직접 띄우고 핫리로드 소켓과 게임 소켓의 공존, 새로고침 복귀를 확인한 뒤 종료합니다.

2026-09-26 경매 식별자 보강 후 로컬 검증: TypeScript 검사, 게임 엔진 19개 + 실제 소켓 통합 6개, Chromium/WebKit 브라우저 테스트 6개 + 개발 모드 테스트 2개, 전체 빌드, Prettier 검사가 통과했습니다. 엔진·소켓 테스트는 누락·잘못된 ID와 이전 라운드·이전 게임의 입찰 거절, 거절 후 최고가·잔액·기록 불변, 정상 입찰·정산을 확인합니다. 브라우저에서는 3인 입찰 → 새로고침 복귀 → 5라운드 종료 → 재경기 후 새 입찰, 낙찰 금액·잔액, 모바일 입력/미션 안내, 봇 입찰/퇴장을 검증했습니다. 이번 자동화에서 390px 화면의 가로 넘침도 확인했습니다. 실제 Safari/iPhone/Android와 모바일 네트워크 전환, 인터넷 배포는 미검증입니다.

## MVP 범위와 운영 전 남은 작업

현재 방과 게임 기록은 단일 서버의 메모리에 저장됩니다. 서버를 재시작하면 게임은 사라집니다. 일시적인 연결 끊김은 30초 동안 복귀할 수 있으며, 시간이 지나면 다른 참가자는 게임을 계속할 수 있습니다. 연습방의 상대는 규칙으로 움직이는 봇입니다.

경매 식별자를 이용한 입찰 검증까지 구현했습니다. 다음 작업은 실제 모바일 기기에서 초대부터 재경기까지 완주하며 불편을 확인하는 것입니다. 단계별 상태와 완료 기준은 [다음 작업 계획서](docs/NEXT_STEPS.md)에 정리했습니다.

실제 인터넷 배포, 운영용 접속 제한과 CI, 장시간 부하 및 실제 모바일 기기 검증은 남아 있습니다. 다중 서버/Redis, 영구 전적, 계정 인증은 플레이·운영 요구가 확인된 뒤 검토합니다.
